News — three positions on what the page is for

Drawn at 390 px. All three are live — type in the search, tap the filters, tap a row. Real post titles from content/news/.

Two features on this page have never rendered. The filter chips need both kinds to exist (showFilter = updates.length > 0 && notices.length > 0) and there are zero notices — the only file in notices/ is _placeholder.mdx, which posts.ts excludes. And pagination needs more than NEWS_PAGE_SIZE = 15 posts; there are nine. So today the live page is a header, an entry count and a list — about 60 lines of built UI nobody has seen.
What is missing is search. CharacterBrowser is the QOL benchmark in AGENTS.md — search, sort, filter sheet, active count. News has no way to find the patch note that mentioned a thing. With nine posts that is survivable; it is the first thing to break at thirty.

A — The feed, tightened

Keeps today's shape and fixes what is measurably wrong: search added, the dead pagination dropped until there is something to paginate, the gutter brought onto the system. Position: news is a list — make the list good. Least to build, least to argue about.

The post page itself is in decent shape and is not redrawn here: back link, kind badge, title, date and reading time, the frontmatter summary as a standfirst, then older/newer steps. The only changes it needs are the same two structural ones as the index — the px-6 gutter and the hand-typed shell both move onto <Screen width="read">, whose --container-read is 42rem, exactly the max-w-2xl it already uses.
A behaviour worth deciding on, whichever option wins. "Unread" is one date in localStorage, not per-post: opening the index calls markNewsViewed(latestNewsDate), which marks everything read — including posts you never opened. So the per-row New badge really means "posted since you last opened this page". That is a legitimate model and plenty of games use it, but the UI reads as per-post tracking. Option B leans on it hardest, so it matters most there.
My pick: A now, B later. At nine posts B's unread block is often empty and C's filters are decoration. A fixes everything that is actually broken and adds the one thing genuinely missing. B becomes the right answer the moment the game has players returning after a gap — and it needs the per-post read decision above settled first.
