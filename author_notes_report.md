**Bug: Chiara's "Damage reduction" text vanishing, showing only "↑ 30% ↑ for 1 turn".** Root cause: `mechanicGlossary.ts`'s `keywordCategories` tagged `"damage reduction"` as category `"buff"`. In `KeyworkHighlighter.tsx`, any keyword categorized `buff`/`debuff` gets its literal text SUBSTITUTED by an arrow icon when `showStatArrows` is on (Dokkan-style: the arrow stands in for a verb like "raises"/"lowers") — correct for actual verbs, wrong for `"damage reduction"`, which is a stat name Chiara's own text states explicitly, immediately followed by her own authored 👆 (which itself renders as a second arrow). Result: word eaten, leaving two arrows. Initially recategorized `"damage reduction"` to `"stance"`, but Tanveer corrected: damage reduction (and evade chance) aren't stance-specific — they're general raisable/lowerable effect stats, not tied to a stance mechanic. Added a new `"effect"` value to the `KeywordCategory` union (alongside offense/debuff/heal/buff/stance/cancel) and recategorized both `"damage reduction"` and `"evade"` to `"effect"` in `mechanicGlossary.ts`. `arrowDirectionForKeyword` only substitutes for `buff`/`debuff`, so `"effect"` behaves like `"stance"` did (no substitution) but is now semantically accurate. Not touched but same latent risk if ever typed next to an explicit arrow in a passive: `"debuff immunity"` (`buff`) and `"damage taken"` (`debuff`) — neither is currently used that way in any passive text, so left as-is. `npm run check` green (409/409) after.
